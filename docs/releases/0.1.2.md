# Show-Tree 0.1.2

Show-Tree 0.1.2 adds a native persistent `.showtree` format for Nushell, so a tree can be saved as structured data, reopened later, and continue behaving like a Show-Tree value in ordinary pipelines.

## Highlights

- Adds `.showtree` as the explicit native persistence extension. `show-tree ... | save snapshot.showtree` stores the current native rows and enough hierarchy information to reconstruct the same forest later.
- `open snapshot.showtree` uses Nushell's normal custom-format discovery through `from showtree`, restores native rows plus Show-Tree metadata, and therefore renders automatically as the R3CLI tree in the REPL.
- Reopened snapshots remain ordinary Nushell data. Filters, sorting and other row-preserving transformations continue to produce truthful reconstructed trees.
- Adds explicit `to showtree` and `from showtree` converters. The extension is never appended implicitly; users choose persistence either by naming a `.showtree` file or by invoking the converter.
- The on-disk format is a versioned NUON envelope with `format`, `schema_version`, `producer_version`, `rows`, and minimal `lineage` fields. NUON preserves Nushell-native values such as `filesize` without degrading them to ad-hoc JSON conventions.
- Filtered snapshots are self-contained. Only rows that survive the pipeline are persisted, and parent relationships are recomputed from those surviving filesystem paths, so removed nodes are not hidden inside the file as stale lineage.
- `open --raw snapshot.showtree` preserves Nushell's native raw semantics and returns the serialized envelope instead of parsing it.
- `save --raw snapshot.showtree` likewise bypasses the custom `.showtree` serializer and delegates the original value to Nushell's builtin raw save path; `--raw` is not overloaded with a Show-Tree-specific meaning.
- Saving a Show-Tree value to any other filename still writes the human tree introduced in 0.1.1. No automatic `.showtree` suffix, `--render`, or output-path option is added.
- Explicit machine conversions remain explicit: `to json`, `to nuon`, `table`, and other renderers consume the native rows before normal saving.
- Invalid `.showtree` envelopes are validated before metadata is restored, including shape checks, path uniqueness, parent consistency, cycle rejection, and unsupported future schema versions.
- PowerShell traversal and pipeline-to-file behavior are unchanged; only its displayed product version advances to 0.1.2.

## Validation

CI covers `.showtree` extension-driven save/open round trips, explicit `to showtree` / `from showtree` conversion, filtered snapshot lineage, reopened-tree filtering, raw opening, future-schema rejection, normal human tree saves, JSON serialization, unrelated builtin-save delegation, and the existing structured-row and R3CLI display contracts. A pseudo-terminal test verifies that `open snapshot.showtree` really renders as a tree in a live Nushell REPL rather than merely carrying metadata in an isolated unit test.

The Windows installation job verifies that the generated `config.nu` imports `to showtree`, `from showtree`, and the dedicated save wrapper exactly once, then exercises both human-text saving and `.showtree` reopening through the installed integration. Existing PowerShell pipeline output, repair installation, idempotent reinstall, and vendored R3CLI integrity checks remain in the suite.

# Show-Tree 0.1.5

Show-Tree 0.1.5 makes the human tree cleaner and removes the main quadratic work from Nushell tree reconstruction.

## Cleaner folder presentation

- Replaces the textual `[Folder]` suffix with the Unicode folder glyph `📁` in both Nushell and PowerShell.
- The folder glyph is part of the visual prefix, so nested directories render as `├── 📁 src` while files remain visually lighter and do not receive a redundant file icon.
- Root directories use the same convention: `📁 D:\Tools\Show-Tree`.
- Human-tree saves use the same glyph and continue to contain no ANSI escape sequences.
- The native row contract and `.showtree` format are unchanged; the glyph is presentation only.

## Faster Nushell renderer

The previous renderer repeatedly scanned the complete visible-row list to find each node's children and repeatedly scanned lineage while resolving parents. Large transformed trees therefore accumulated quadratic work even though the underlying tree relationship was already known.

0.1.5 builds reusable indexes once per render:

- visible paths are indexed once;
- lineage paths are indexed once;
- effective visible parents are resolved through those indexes;
- visible rows are grouped by effective parent once;
- recursive rendering reads each node's already-grouped children instead of rescanning every row.

This preserves filtering, sorting, orphan promotion, `$ans.last`, human-tree saving, and reopened `.showtree` behavior while making the common intact-tree render plan effectively linear before sibling ordering and output emission.

## Performance validation

Synthetic flat-tree benchmarks in the same GitHub Actions Linux CI environment showed:

| Rows | 0.1.4-style renderer | 0.1.5 renderer | Improvement |
| ---: | ---: | ---: | ---: |
| 501 | 1.108 s | 0.503 s | ~2.2× |
| 2,001 | 11.701 s | 2.195 s | ~5.3× |

Increasing the test from 501 to 2,001 rows is a 4× input increase. The old implementation took about 10.6× as long; the indexed renderer takes about 4.4× as long.

A second benchmark isolates relationship planning from text emission. It measured roughly 146 ms for 2,001 rows and 779 ms for 8,001 rows. CI now enforces generous scaling and absolute-time ceilings so a return to full-list scans is caught automatically.

The Windows traversal path was benchmarked separately. A proposed hash-like index for Windows visible filenames made the 1,500-file default traversal slower across the measured CI runs (about 828 ms before versus 982 ms with the index), so that change was deliberately rejected. The existing `du` plus platform-visible-name approach remains in place rather than shipping an optimization that only looks clever on paper.

## Compatibility

- No command-line options change in 0.1.5.
- Default hidden-entry behavior and `--all` / `--short` semantics are unchanged from 0.1.4.
- `.showtree` remains schema version 1; `producer_version` advances to 0.1.5.
- The public Nushell row contract remains `name`, `type`, `size`, `children`, and `path`.
- PowerShell pipeline-to-file behavior and Nushell tree-aware `save` remain unchanged apart from the folder glyph.

## Tests

CI now includes dedicated folder-glyph rendering tests for Nushell and PowerShell, renderer performance/scaling benchmarks, the existing Windows Hidden-attribute traversal benchmark, and all previous structured-output, persistence, REPL, installer, and pipeline regression coverage.
